# w-daemon-auth — loopback auth key for the daemon HTTP surface

Jordan ruling 2026-08-28 (verbatim intent): "the CLI must check and pass a key
that is generated by daemon and stored in ~/.config/flowspace3 or wherever our
config lives so that not just anything can call it."

## Requirement

1. On startup the daemon GENERATES a random key (regenerate per boot is fine;
   stable-until-rotated also acceptable — state your choice + why) and writes
   it into the resolved config dir (`fs3_core::resolve_config_dir`, honouring
   CONFIG_DIR_ENV) as a file with 0600 perms (e.g. `daemon.key`).
2. Every daemon HTTP request must present the key (Authorization bearer header
   or an `x-fs3-key` header — pick one, state it) or be rejected 401 with a
   proper JSON error envelope naming the fix (`next_action` pointing at the key
   file / daemon restart).
3. The CLI reads the key from the same config dir and attaches it to every
   daemon call. A missing/stale key produces an actionable error, not a hang.
4. `flowspace3 doctor` gains a row proving auth is configured and accepted.
5. Envelope bytes on SUCCESS paths must not change (agent contract). The 401
   is a new surface; document it in the self-teaching docs the way other errors
   are documented.
