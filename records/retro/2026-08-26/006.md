# Retro — w-local-embed (local ONNX embeddings, validate + adapter)

Three things generalise beyond this packet.

**Measuring beat reading.** The librarian returned `NOT FOUND` for three
properties that decided the design — whether output is L2-normalised, whether
`TextEmbedding` is `Send + Sync`, and whether cross-call embeddings are stable
enough for the contract's 0.999 floor. A twenty-line throwaway binary answered
all three in one run (`1.000000`, compile-asserted, `1.000000000`). Stage 1
existing as a separate stage is why the adapter needed no rework.

**The tests found the defects, not the review.** Every trap in
`docs/services/local-embeddings.md` — the CWD-relative cache, the
`BAAI/…` name that does not resolve, the `HashMap`-ordered error message, the
concurrent cold-cache collision — surfaced as a red test, not as a careful read.
The one I would have shipped is the model name: `fastembed` reports
`Xenova/bge-small-en-v1.5`, so every fs2 config in existence would have been
rejected as "unknown model" while being plainly correct.

**Reasoning rots into comments unless a test holds it.** `key()` is
`catalogue-name@dimensions` because `fastembed` maps two genuinely different
vector spaces onto one HuggingFace code at one width. That argument now has a
test asserting *both* of its premises, so a future `fastembed` release that
moves either one fails loudly instead of quietly mis-keying enrichment rows.
