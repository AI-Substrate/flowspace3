## 0. The one-paragraph brief

Every agent harness already writes its own session state to disk — Claude Code, omp/pi, Copilot CLI, Copilot VS Code, Cursor, Codex, Gemini, Droid, Windsurf — each in its own dialect, its own location, its own flush discipline. Two systems in the substrate org have tried to read them: the engineering-harness **`harness telemetry`** family (counts-only, OTLP-shaped, refs-as-transport; now disabled-not-deleted behind git-ai) and **flowspace3's conversation sources** (full-content transcripts, four readers behind one frozen trait, a daemon poller that runs them). git-ai was studied as a possible single source and rejected: it is a faithful *collector* but not a *normaliser* — it stores each harness's raw record and its capture silently stalls. The new product is the thing neither built: **one library + CLI that reads any harness's native store and emits ONE standard stream** (sessions → turns/events with explicit precision and honest absence), which flowspace3, the harness, pij, and anything else can consume without owning a dialect parser. Build it as a data-table-driven adapter set behind a frozen seam, with liveness and spend visibility designed in from day one.

## 2. Measured facts that must shape the design

1. **git-ai is faithful but not normalised.** My own session: 6,001/6,002 assistant message ids, 27,636/27,638 record uuids, largest tool_result 55,871/55,881 chars, 15/15 subagents parent-linked — a byte-faithful copy. But `v.0` is the harness's raw record (Claude jsonl line; copilot event; omp record; codex payload; cursor `turn_ended` marker only). One dialect parser per harness is still required. → **git-ai can be an input; it cannot be the standard.**
2. **git-ai capture stalls silently.** My session's stream stopped at byte 84,661,106 on day 10 with `processing_errors=0`; a 13-tool-call session was never captured; its sweep only visits `~/.claude-alt` and `~/.copilot`, never `~/.claude`; omp rows stopped 09-02; every session's last turn is structurally absent (nothing fires after the last `PostToolUse`). → **liveness must be a first-class, visible property; watermark-vs-size in the UI.**
3. **Harness dialects differ in ways that matter:** Claude writes one line per content BLOCK and repeats `message.id` (grouping rule is FROZEN in flowspace3 — change it and every stored conversation doubles); omp rewrites a fixed-width title slot in place and persists lazily (a session id can exist before its file does); Cursor flushes at turn boundaries so mid-run reads see a 2-line stub; Copilot VS Code lives in SQLite; Codex tokens arrive only in a rollout ledger; Copilot totals only at graceful shutdown. → **per-adapter cursor/precision semantics, not one loop.**
4. **Identity is file-derived or it is wrong.** pij's `harness_session` is rewritten on every session switch and omp persists lazily — a seat row can name a session with no file. flowspace3's poller derives `(harness, session_id, folder)` from filenames + the record's own `cwd`. The pij↔harness↔git-ai session UUID *is* the same for Claude Code and Copilot CLI (harness `gitai-collector.md:96-99`), which is what makes fleet lineage joinable. → **the store is the identity; registries are joins, never sources.**
5. **Spend is the cost; CPU is free.** Finding changed files is `stat` vs cursor; indexing is LLM summarisation. One 16 MB Claude session = 3,109 summarize jobs on first ingest; re-ingest of an unchanged session = 0 (proven at the job level three ways). → **the standardiser must expose "what is new since cursor X" as a primitive, with dedupe keys the consumer can trust, so no downstream ever re-pays.**
6. **"Behind" needs a notion of "asked, and the answer was nothing."** Zero-record sessions (7 real files on this machine) and cwd-less files churned forever until a stamped negative acknowledgement was added; a lag counter keyed on passes (not attempts) read a saturated runner as dead. → **design the negative-ack and the attempt-keyed liveness in from the start; the reviewer's F1/F2/D1 in `docs/plans/018-convo-poller/assets/reviews/cross-model-review.md` are the reference.**
7. **Counts-only is a structural property, not a review.** The harness's serializer picks fields per kind and never spreads input; Copilot VS Code word counts are computed *inside the SQL* so text never enters the process. → **two output modes (full-content / counts-only) must be two serializers, not one with a flag.**
8. **Toolchain reality:** an Xcode update silently broke every release build for two days (`ort-sys` cached a clang-17 path). Not this product's bug, but its CI must not depend on a machine's Xcode state — keep the core pure Rust/TS with no native ML deps.

## 3. Product shape (proposal — the new agent owns the final architecture)

- **Core = a frozen seam** (`Source` trait / interface): `discover(root) -> [SessionRef]`, `resolve(ref) -> [SessionFile]`, `read_incremental(file, cursor) -> Batch{records, cursor, rescanned}`, mirroring flowspace3's `ConversationSource` (which shipped FOUR implementations on day one against a frozen shape — the seam earned its existence). Adapters are rows in a data table where possible (the harness's `agent-matrix.ts` pattern: config dir, env override kind, file list, event keys), code only where a dialect demands it.
- **One standard stream**, two profiles: `content` (turns with role/items/tool calls/results/subagent links) and `counts` (the harness's closed 18-kind event vocabulary — `prompt, turn, usage, tools, skill, flow, branch, checks, command_exit, subagent, compaction, model, api_error, artifact, file, mark…`). Every event carries `t_precision ∈ {exact, anchored, interpolated, interval}` and every absent scalar is `null`, every absent collection present-and-empty — never estimated.
- **Identity** from the store: `(harness, session_id, folder)` derived from path + in-record `cwd`; an optional join layer for pij seat ids and git-ai session ids, clearly labelled as joins.
- **Cursors** are per session FILE (sidecars have their own), durable, with rotation/truncation/identity-change detection (flowspace3 `tail.rs` is the reference; its non-Unix `(0,0)` identity limitation is documented).
- **Liveness + spend as outputs, not logs:** per store `{tracked, behind, in_flight, acknowledged_nothing, unreadable, newest_read_at, state ∈ flowing|stalled|disabled}` with the stall rule keyed on attempts observed, plus per-poll `{records_read, new, deduped}` so a consumer can prove it never re-paid.
- **Sinks:** a CLI (`<name> read --harness claude --session <id> --since <cursor> --profile content|counts`), a library, and an OTLP emitter for the counts profile (the harness already proved OTLP Logs+Metrics ingest with zero translation).
- **Consents are two switches** ("read my sessions" ≠ "install a hook"); default read-only over stores that already exist; hooks are optional accelerators, never the only trigger.

## 4. What NOT to do (each one cost us)

- Do not key identity on a registry field (pij `harness_session`); do not trust `dedupe_key` indexes to cover terminal rows (prod's is partial over live rows only); do not count a pending job as an attempt; do not log the aggregate and hide the per-file receipt; do not hand-edit generated docs; do not let a test's fake HOME be the real one (seal it in the shared harness — flowspace3 `testkit::sealed`); do not read `$?` after a pipe.
- Do not assume git-ai's sweep covers the default config dir, or that a green `git-ai` watermark means capture is current.
- Do not merge the harness's counts-only guarantee with a content profile in one serializer.

## 6. How `harness telemetry` worked before git-ai (researched 2026-09-07 by a subagent using flowspace3 + source reads; file:line cited)

(`$CLI` = `~/.npm-global/lib/node_modules/@ai-substrate/engineering-harness/harness/cli/src`)

**6.1 The verb family** (`$CLI/acts/telemetry.ts`): `ls` (inventory sessions under remote `refs/harness-telemetry/**`), `pull` (deterministic bundle, integrity-verifiable), `sync` (roll buffered segments into one ref per session at `refs/harness-telemetry/<YYYY>/<MM>/<DD>/<session>`, force-push; first run migrates old per-capture-date refs), `mark` (agent self-attestation: slug-shaped `--kind/--verdict` + integer counts, no free text), `get <pij-id>` (counts-only evidence object, buffer first then ref, `source: buffer|ref|buffer+ref`), `get-fleet <root>` (orchestrator + children → one `FleetEvidence`), `session save` (segments → schema-valid `SessionExport`), `report`, `report-render`, `insights`, `sweep` (month-scoped composition, `.sweep-cache.json`).
**Where data lived:** live buffer `.harness/temp/telemetry/<session>/<seq>.json` + `<session>.cursor` + `<session>.liveness.json` (self-ignored so `git status` is byte-identical across a capture); durable = git refs via plumbing (never index/worktree; invisible to PRs and merge-base walks); SQLite only ever read (Cursor IDE store, Copilot-Chat `session-store.db`) through a read-only port.
**Triggers:** a capture preamble on EVERY `harness <verb>` (fail-safe wrapper, cannot alter host stdout/exit); the `harness checks` exit chokepoint auto-pushes; a post-commit hook runs one hourly-debounced `sync` (+ liveness reconciliation); manual `sync`. Env: `HARNESS_TELEMETRY_CAPTURE=1` opt-in, `HARNESS_NO_TELEMETRY=1` hard-off, `HARNESS_NO_TELEMETRY_AUTOSYNC=1`, `HARNESS_NO_COLLECTOR=1` (deliberately not an alias — two consents).

**6.2 Harnesses it could read** — exactly four telemetry adapters (`$CLI/services/telemetry/adapters/index.ts:30-35`): **claude-code** (`~/.claude/projects/<mangled cwd>/<id>.jsonl`, exact timestamps, full result envelope → `checks` + `command_exit`); **copilot-cli** (`~/.copilot/session-state/<id>/events.jsonl` + `~/.copilot/logs/process-*.log`, id from `COPILOT_AGENT_SESSION_ID`, per-interaction tokens); **copilot-vscode** (SQLite `…/globalStorage/github.copilot-chat/session-store.db`, detected by `AI_AGENT=github_copilot_vscode_agent`, resolved by cwd + latest `updated_at`, word counts computed INSIDE the SQL, tokens `null`); **cursor-agent** (`CURSOR_CONVERSATION_ID` + `AGENT_TRANSCRIPTS`, no transcript timestamps → events ANCHORED to IDE-store bubble `createdAt`, tokens permanently `null`). Side-channel ledgers: **codex** (`~/.codex/sessions/<Y>/<M>/<D>/rollout-*.jsonl`, last `token_count`), **copilot** (`session.shutdown` carries `totalNanoAiu`, `tokenDetails`, `totalApiDurationMs` — only at graceful end). Hook-install matrix (`$CLI/services/hooks/agent-matrix.ts:215-310`, "one table, no per-agent code"): claude-code (`~/.claude/settings.json`, `PreToolUse/PostToolUse`, nested, matcher `*`), cursor (`~/.cursor/hooks.json`, flat, `version:1`), gemini (`~/.gemini/settings.json`, `BeforeTool/AfterTool`), droid (`~/.factory/settings.json`), firebender (`~/.firebender/hooks.json`, matcher rejected), github-copilot (`~/.copilot/hooks/` drop-in dir), windsurf (`~/.codeium/hooks.json` AND `windsurf/hooks.json`, five cascade events). **No pi/omp adapter or hook row exists anywhere** — pi appears only as a label in the pij registry.

**6.3 Relation to git-ai** (`docs/how/gitai-collector.md`): git-ai replaced WHO captures (harness-on-every-verb → git-ai agent hooks), the default (ON → off in code), and the attribution grain (per-session counts → per-line per-commit notes at `refs/notes/ai`, schema `authorship/3.0.0`). The harness kept the whole READ path (ungated; test-asserted never to import the capture gate) and the legacy producer ("disabled, not deleted"). `harness commit` probes the collector ingress socket, commits with one non-chained command, and verifies a note landed or buffers trace2 and names the recovery; `harness doctor telemetry-nudge` drains that buffer (rotate-by-rename, replay whole segment into the `af_unix` socket, delete only when every owned sha carries a note). A trace2 guard refuses to run `git-ai install-hooks` when global trace2 config is non-empty (their installer does a machine-wide `--remove-section trace2` and fails open on unknown args).

**6.4 The normalised shape:** `segment.schema.json` ("Harness telemetry segment (counts-only)") → **event stream v2.0**, a CLOSED 18-kind vocabulary (`prompt, turn, usage, tools, skill, flow, flow_log, branch, harness, checks, command_exit, subagent, compaction, model, api_error, artifact, file, mark`; `$CLI/services/telemetry/events.ts:56-95`), each event `t + kind + name + numbers`, with `t_precision ∈ exact|anchored|interpolated|interval` (`:36-44`) and `capture_mode: 'reconciled'` as the only legal value (liveness proven by the field's ABSENCE). The **rollup** is a pure recomputable function of the stream (gap before a prompt ≤5 min = human, >5 min = idle, else agent; `working_ratio`). Storage is **OTLP Logs + Metrics** directly (`otlp/logs.ts`, `metrics.ts`; `docs/how/telemetry/otlp.md`). `SessionExport` v1 = `{schema_version, identity, source, summary, signals}`, `additionalProperties: true`. The **join table** is the pij registry (`~/.pij/<id>.json`, read-only two-way map `pij_id ⇄ harness_session_id` + `harness`, `transcript_path`, `spawned_by`, `model`, `relay`); pij's bound id and git-ai's are the SAME UUID for Claude Code and Copilot CLI.

**6.5 What broke / was abandoned:** the git-ai swap accepted three regressions — fleet lineage went dark, Copilot CLI lost model + token data ("the sharpest measurable regression"), no semantic/flow capture. Lazy-flushing harnesses (Cursor) strand evidence unless a liveness marker + stall/residue/lost detectors reconcile in a `[6h, 14d)` window — and per-worktree markers die with the worktree. Pre-069 shards have no `control` field (checks-before-push discipline permanently unmeasurable; reports emit `coverage.push_signatures_unavailable`, never a false zero). The clobber-on-rewrite bug buried segments under per-date refs (plan 049 migration unions across ref history). Writing Cursor's flat hook shape into `~/.claude/settings.json` DISABLED every setting in that file (three agents hit). "direct-verified" proved a note EXISTS, not that it is CORRECT (two seats reproduced VERIFIED commits with humans-only attribution). Plan 063 (`docs/plans/archive/063-systemic-telemetry-repair/`) records the token-darkness repairs and the explicit deferrals (turn-duration joining, model-interval provenance, plan attribution across ref rewrites, lifecycle semantics).

**6.6 Reusable ideas, each tied to a file read:** agent differences as a DATA TABLE (`agent-matrix.ts`); closed vocabulary + allowlist serializer that never spreads input (`events.ts`); `t_precision` first-class; derived rollup recomputable from the stream; honest-absence shape rules (null scalars, present-empty collections); liveness by absence (`capture_mode`); counts computed at the SQL boundary (`copilot-vscode-adapter.ts`); read-only never-throwing readers degrading to `measured:false` with typed reasons (`pij-registry.ts`, `codex-ledger.ts`); OTLP as the storage shape; rotate-by-rename before reading a buffer (`nudge.ts:35-42`); refs as a durable channel invisible to git status; two separate consents; the cross-layer session-UUID join.

**6.7 flowspace3 feedback from that research** (recorded as backlog row 202): 4 of 7 searches hit; the 3 misses shared a shape — verb-named queries lost to conversation turns, two returned the subagent's OWN prompt at 1.0, and `harness/cli/src` code barely surfaced. Every concrete answer above came from reading source. The new product's own docs and code must be indexed as CODE, and it should ship with a small eval of "does search find the adapter for harness X" from day one.

## Addendum 2026-09-07T00:20Z — first in-situ finding from the poller, relevant to this product's design
Ninety minutes after the bounce the conversations row read `stalled`: eleven sessions whose recorded cwd was under `/tmp/…` could never be resolved because flowspace3 slugs the RECORDED cwd (`-tmp-x`) while omp slugs the REALPATH and wraps non-home paths (`--private-tmp-x--`); and a FAILED terminal attempt carried no negative acknowledgement, so each was resubmitted every pass (backlog row 204). Two lessons for the standardiser: never re-derive a store path from a recorded cwd when you already hold the file's real directory; and every terminal outcome — success-with-nothing AND failure — must produce a stamped acknowledgement, or a permanently unreadable file becomes permanent churn.
